PLATE I

System architecture

The load-bearing decision is not a component — it is a boundary. Customer source never leaves the customer's machine, and exactly one line crosses outward: three digests with no content in them. Everything else in the drawing exists to make a claim checkable by someone who does not trust us.

PLATE II

The production cycle

What a run actually does to a customer's codebase, and — more to the point — where it is allowed to stop. Three of the seven stations can end the run with no output at all. That is the feature: a migration tool's real character is what it does outside its depth, and every exit below is a named refusal rather than a confident-looking approximation.

SealedPhase 0 · stop 01 · on or before 2026-08-16

The benchmark was sealed before the solution existed

RELIAN-BENCH's success criteria were committed and Ed25519-signed before any transform work was scored against them. That ordering is the whole point: a bar you can move after seeing the result is not a bar.

Version 1.2 seals 29 files under payload a8695c2c…, key fingerprint 233bb440… — seven COBOL programs, 425 held-out vectors and 89 public ones. The thresholds live in the ledger, not in a README: held-out BER ≥ 0.95, build rate 1.00, JaCoCo branch coverage ≥ 0.80.

The held-out vectors are not in this repository and are never read by an agent. They are scored in CI on main only — because a score returned on every push is a feedback channel, and a feedback channel is something you can fit against one commit at a time without ever intending to.

Stands on this

  • "Candidate X scored Y on criteria nobody could tune against"
  • Re-verification by a recipient, from the ledger alone

Does not stand on this

  • Any statement about COBOL outside the sealed corpus
  • Any claim the benchmark itself is representative of a customer estate
MeasuredPhase 0 · stop 02 · 2026-08-16 → 08-17

The deterministic transpiler clears its own bar

C1 is the pipeline's transform core and there is no model anywhere in that path. At the moment v1.2 was sealed, C1 was red on it: BER 0.7176, building 6 of 7 programs. That red is the receipt that the criteria came first.

WP-1.5.4 and WP-1.5.5 closed it. Measured in CI on PR #15 at commit 8c676e9: 425 of 425 held-out vectors match across all seven programs, build rate 1.0000, JaCoCo branch coverage 0.8854 against a bar of 0.80.

Scope, stated rather than implied. The supported subset is COBOL-85: COMP-3 arithmetic, EVALUATE, PERFORM VARYING, OCCURS/SEARCH, INSPECT, edited pictures, VALUE, and CONTINUE/GOBACK/EXIT PROGRAM. Numeric business logic is emitted as BigDecimal with explicit COBOL rounding — ROUNDED is HALF_UP, an unrounded COMPUTE is DOWN.

Stands on this

  • Behavioral equivalence on the sealed corpus, held-out
  • Reproducibility — a second pass emits identical bytes

Does not stand on this

  • CICS, VSAM, JCL, embedded SQL, or copybooks in the transform path
  • IBM Enterprise COBOL — the oracle is GnuCOBOL 3.1.2.0
ShippedPhase 1 · stop 03 · 2026-08-16

The assessment engine — the first thing a customer can buy

WP-1.1 through WP-1.9 built src/assessment/: intake, LOC, cyclomatic complexity, construct coverage, risk tiering, report, CLI. It is read-only over customer source and fully offline — nothing in the package opens a socket or calls a model.

Determinism is asserted three ways, not assumed: two runs over the same tree produce byte-identical JSON and the same report_hash, and a CRLF copy of a tree scores identically to its LF original.

The capability list is not hand-maintained. The coverage analyzer reads SUPPORTED_STATEMENTS off the transpiler at call time and probes DATA DIVISION features by running real programs through it. Teach the transpiler a new verb and the report changes on the next run with nobody editing a list. Data features are reported three-state — supported, accepted but ignored, unsupported — because a clause that parses and is then discarded is not a clause you support, and conflating the two is how a migration silently loses semantics.

Stands on this

  • A priced, deliverable read-only assessment
  • Construct inventories on estates far outside the transpiler's subset

Does not stand on this

  • Any migration claim — assessment measures distance, not equivalence
  • Effort or cost forecasting; no such model exists
ShippedPhase 1 · stop 04 · 2026-08-16

Honest failure wired down to the statement

Before WP-1.2 there was no else branch in the transpiler's statement dispatch and no unsupported() anywhere. An unsupported verb that began a statement was silently discarded; one that followed a statement was absorbed into its predecessor and surfaced later as a misattributed error. Honest failure existed only at whole-program granularity, and only for two of the four observed failure shapes.

The if/elif chain became a dispatch table with an unsupported(verb, line_no) fall-through, so a refusal now names the verb and the line that carried it.

The refactor was gated on bytes, not on opinion. All five generated Java files regenerated SHA-256-identical before and after, and identical to the committed candidates. A behavior-preserving change that cannot be shown to preserve bytes is a change nobody should merge into a transform.

Stands on this

  • "Unsupported input produces a diagnosis, not output"
  • A demand signal ranked by real occurrence counts

Does not stand on this

  • Completeness of the diagnosis for constructs never exercised
ShippedPhase 2 · stop 05 · 2026-08-20

The limbs that produced numbers nobody measured were deleted

Three things left the tree in one phase, and their absence is now part of the architecture.

The risk-scoring limb (R1). It retrained a gradient-boosted model every twenty migrations on rows whose "cognitive complexity" feature was cyclomatic complexity × 1.2 — a fabricated input feeding a fabricated score, tightening on itself. Both the scorer and its pattern store were deleted. risk_score and test_coverage are now None by construction, not by configuration.

The generative-AI semantic analysis stage and the LLM test generator (R6). Both sent customer source code to a hosted model. They were deleted rather than flagged off, because a flag can be flipped and a deleted call cannot. semantic_score now has exactly one source: Stage 6 differential execution against the legacy oracle — which is the only measurement of semantic preservation this pipeline ever actually had. A model's self-reported confidence was never one.

Alongside that: the environment was pinned in requirements.lock, a toolchain guard added, and CI switched from "no failures" to asserting the exact test triple, so a test that quietly stops being collected turns the build red.

Stands on this

  • "No customer source reaches a generative model" — R6, structurally
  • Every emitted metric traces to a process that ran

Does not stand on this

  • Risk prioritisation of any kind — the capability is gone, not hidden
SealedPhase 2 · stop 06 · 2026-08-21

A second benchmark, sealed before the code it judges

R7 is bench-first: nothing is "supported" until a sealed benchmark covers it, and the bench commit must predate the merge. So the copybook work was gated on a benchmark that did not yet exist, and building it came first.

RELIAN-DISCOVERY-BENCH v0.1 — 15 copybooks, 124 elementary fields, 170 probe rows, 16 variants, 9 conditions and 6 gap rows — has its oracle layouts generated by GnuCOBOL 3.1.2.0 and was sealed under the same benchmark key on 2026-08-21. CI enforces the ledger on every run, and discovery-bench/ became frozen the moment the tag existed.

Stands on this

  • Layout claims measured against an oracle that predates the code

Does not stand on this

  • IBM Enterprise COBOL layout semantics — the oracle is GnuCOBOL
  • Copybook support inside the transform path; this is discovery only
MeasuredPhase 2 · stop 07 · 2026-08-21

Copybook resolver and static layout engine

src/discovery/copybook.py resolves the COPY fan-in graph and reports the missing-copybook table. layout.py computes static record layouts: offsets, lengths, SYNC padding, REDEFINES, OCCURS DEPENDING ON, RENAMES.

Round-trip against the sealed oracle: 186 of 186, tolerance zero. Not "within a byte" — identical.

Gaps compare by projection, not by label. A padding byte cannot be renamed into agreement with the oracle, which is the obvious way a layout engine passes a test it should fail. Two limitations are reported by the tool rather than absorbed by it, and None never silently becomes zero.

Stands on this

  • Record layouts a customer can check against their own DDL
  • A named, enumerated missing-copybook table

Does not stand on this

  • File inventory, lineage, or target-schema DDL — stop 09
We are hereMeasuredPhase 2 · stop 08 · 2026-08-21 · HEAD 179fe59

The signed Data Discovery report

python3 -m src.discovery.cli report build emits a canonical report.json, a Markdown rendering that names the JSON as authoritative, a manifest of digests, and an Ed25519 instance signature over that manifest. If a signing key cannot be obtained it writes nothing — an unsigned artifact that looks signed is worse than no artifact at all.

Custody is split across two keys so that rotating or compromising one cannot put the other's claims in question. The benchmark seal key 233bb440… signs ledgers and never a customer deliverable; the Visionblox release key 91e3a404… countersigns reports and never a benchmark. The countersigning tool refuses the benchmark fingerprint outright.

Exactly one line crosses the customer perimeter: manifest hash, report id, instance fingerprint. Three digests, no content. Recipients check the result with verify_report.py --pin-fingerprint, which has four independently-failing layers and prints its own SHA-256 before it says anything else. The pin has no default, because without one a report re-signed under any key at all passes every internally-consistent check.

Stated because it is true and would be easy to leave out: no countersignature has ever been issued. Both dry runs read VALID AND UNATTESTED. Suite at this commit: 852 passed, 10 skipped, 0 failed.

Stands on this

  • A verifiable discovery deliverable a recipient can check without trusting us
  • Perimeter compliance demonstrated by a leak test, not asserted

Does not stand on this

  • Any countersigned artifact — none exists
  • PDF rendering; Markdown is the one derived rendering
  • File inventory, lineage, target-schema DDL
Not builtPhase 3 · stop 09 · WP-2.4

File inventory, lineage, and target-schema DDL

The next work package: a file inventory drawn from SELECT / FD / JCL DD statements, data lineage across programs, target-schema DDL generation, and a data-dictionary rendering.

All four are absent today rather than approximated, and the shipped report says so on its own face rather than leaving a reader to infer it.

What standing here would require: the four surfaces built; discovery-bench extended and re-sealed to cover them, in that order; and their gaps reported by projection the way the layout engine's already are.

Blocking

  • A re-sealed discovery benchmark must precede the merge (R7)
  • Lineage across programs needs a resolved call graph, which does not exist yet
Not builtPhase 3 · stop 10

The first countersigned report

The countersignature flow is proven end to end — but only under a stand-in key generated inside a test. Nothing in this repository has ever held the release key, and nothing ever will: custody is the operator's, and R4 keeps private material out of the repo, out of CI, and out of any agent session.

Two things gate this stop. First, visionblox-release-key-v1.pub — public material, and the one artifact still missing — must reach the repository, so the published fingerprint can be checked against the actual key rather than against a transcription of it. Second, one real engagement whose report the operator countersigns.

Until both happen, every report Relian produces is VALID AND UNATTESTED, and that is the correct label rather than a caveat.

Blocking

  • Public key not yet in the repository
  • No customer engagement has been run
Not builtPhase 4 · stop 11

Corpus v2 and the scope extension it gates

"Migrates COBOL" is licensed today only for the subset the sealed corpus exercises. Extending it is a benchmark action before it is a grammar action: corpus v2 harvests third-party COBOL, seals it, and only then may CICS, VSAM, JCL, embedded SQL or copybooks-in-transform be attempted. Each construct pair earns the word "supported" by clearing held-out CI, and the bench commit must predate the grammar merge.

The distance is already measured, and it is large. Across three real-world corpora the assessment engine found 2,190 unsupported occurrences, and six constructs account for roughly 70% of everything blocking migration: EXIT (368), EXEC (306), CONTINUE (271), WRITE (224), GO TO (186), CALL (183). The cheapest third of that backlog is dispatch-table work with no new semantics.

Construct coverage on those corpora — AWS CardDemo 0.8511, the OMP course corpus 0.6945, GnuCOBOL's own tests 0.5968 — is graded PLAUSIBLE, not VERIFIED, for a specific reason: not one third-party program parsed cleanly under the then-bundled grammar, so all three were analysed through the token-scan fallback. The grammar was replaced at WP-2.0 and these figures have not been re-measured since.

Blocking

  • Corpus v2 not harvested, not sealed
  • Dry runs need re-measuring against the replaced grammar
  • Third-party licensing must be cleared per source
Not builtPhase 4 · stop 12

Attestation that is not simulated

Today's attestation self-identifies as simulated: true, and the pipeline refuses to issue even that over unmeasured values — if Stage 6 did not measure, Stage 7 is skipped outright. The reasoning is worth keeping: signing a fabricated number does not make it true, it makes it tamper-evident, which is strictly worse because it lends the number a guarantee it has not earned.

Retiring the flag needs a real integration; nothing simulated ships (R5), so the flag stays until the integration is real. Symbolic test generation returns empty by construction and stays that way until KLEE is genuinely wired in. The risk model was deleted, not trained — any re-entry starts from zero and is bench-gated like everything else.

Blocking

  • No attestation backend selected or integrated
  • KLEE not integrated; generated-test count is 0 by construction

The five rules this page obeys

  • R1 — a metric is measured or None. Never a constant or a default wearing a measurement's name.
  • R2 — honest failure is a feature. Unsupported input gets a diagnosis, never a silent pass.
  • R5 — nothing simulated ships; where an integration is absent it is said plainly.
  • R7 — bench-first. No construct is "supported" until a sealed benchmark covers it and CI passes.
  • R9 — every externally visible number carries a grade and a basis. See the appendix.

What is safe to say in a room

That Relian assesses a COBOL estate offline and read-only, and produces a signed, independently verifiable discovery report. That its transpiler clears a benchmark sealed before the transpiler was written, on vectors it has never seen. That it refuses rather than approximates.

What is not

That anything has been migrated for a customer. That any report has been countersigned. That the tool handles CICS, VSAM, JCL, embedded SQL, copybooks in the transform path, or IBM Enterprise COBOL semantics. That attestation is real — it self-identifies as simulated, and the pipeline skips it whenever validation was not measured.
