## 1. The violation that was closed

`orchestrator.py:228` awaited `_analyze_semantics()` unconditionally inside `migrate()`. That
method constructed `src.analysis.semantic.SemanticAnalyzer`, which instantiated
`AsyncOpenAI(api_key=os.getenv("OPENAI_API_KEY"))` and placed **customer source code** in the
prompt. `api/main.py` reaches `migrate()`, so the path was live. With no key set it raised and
took an honest fallback; with a key set, customer source left the perimeter. `_generate_tests()`
at `:266` shared the dependency.

Both call sites are deleted. Both methods are deleted. `src/analysis/` is deleted. The three
distributions are out of `pyproject.toml`.

`semantic_score` and `test_coverage` are now `None` **by construction** on this path. Per R1 that
is the honest value, not a degradation: `semantic_score` is set only by Stage 6 differential
validation (measured BER), and `test_coverage` only by a real coverage tool. LLM self-reported
confidence was never a measurement of semantic preservation and is no longer recorded as one.

## 4. Finding raised, not acted on — `src/ml/risk_scorer.py` (R1)

The WP asks that `risk_scorer` be assessed in the same pass: *"if it has no measured model behind
it, it is a constant pretending to be a measurement and comes out too. Record the disposition
either way."* It produced **no sweep hits** — none of the six patterns match it — but the
assessment was performed and is recorded here.

**It does not import any generative-AI client. This is not an R6 issue and does not block this WP.**

**It is an R1 issue.** `RiskScorer.score()` (`src/ml/risk_scorer.py:266`) returns a
`RiskAssessment` whose `confidence` field is a **hardcoded literal**:

```python
if self._is_trained and self.model and HAS_XGBOOST:
    score = float(self.model.predict(dmatrix)[0]) * 100
    confidence = 0.85          # <- constant, presented as a measurement
else:
    score = self._heuristic_score(metrics)
    confidence = 0.70          # <- constant, presented as a measurement
```

Neither `0.85` nor `0.70` is measured. Nothing calibrates them; they do not move with the input.
R1 says a metric is measured or `None` — never a constant presented as a measurement — and it
applies to code, not only to reports. In the default configuration no model file is loaded, so
`_is_trained` is `False` and **every** risk score in practice comes from the heuristic branch: a
deterministic formula over measured metrics, which is a *design constant* composition and would
need that label under R9, carrying `confidence = 0.70` that means nothing.

This reaches an externally visible number: `_score_risk` → `result.risk_score` → the API's
`average_risk_score`.

**Disposition: ESCALATED, not changed.** Two reasons. First, it is outside the instruction for
this pass, which named the generative-AI excision. Second, and more importantly, the fix is a
judgment call the operator owns — `confidence` could become `None`, or the heuristic branch could
be labelled `SPECULATIVE`/design-constant per R9, or the whole scorer could come out as the WP
contemplates. Each choice changes a shipped number, and R1 problems should not be resolved by
whoever happens to be doing an unrelated excision. Recommend a dedicated work package.
